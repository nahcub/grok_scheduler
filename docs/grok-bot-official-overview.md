# Grok Bot 공식 문서 정리: Overview

출처: https://docs.x.ai/grok-bot/overview (xAI 공식 문서, 정리일 2026-11-01)

이 페이지는 개요이고, API·webhook·작업 전달 방식·명령어·루틴 문법·승인 방식·수치 제한·금액은 하위 페이지에 있다고 명시한다. 이 문서는 개요 페이지만 정리한 것이며 하위 페이지는 아직 읽지 않았다. 2차 자료 기반의 [grokbot-research.md](grokbot-research.md)보다 이 문서를 우선한다.

## 1. 개념

- Bot은 이름, 업무, 누적 컨텍스트를 가진 지속형 AI 팀원이다.
- 각 Bot은 브라우저, 파일시스템, 터미널이 있는 **영구 클라우드 컴퓨터**에서 일하므로 실제 도구에서 작업이 끝난다.
- 사용자는 Bot에게 메시지(타이핑, 음성 받아쓰기, 음성 채팅)로 일을 맡긴다.
- 여러 단계에 걸친 앱·웹사이트 작업을 처리하고, 대화에 진행 상황을 올리며, 필요하면 사용자 승인을 요청한다.

## 2. 주요 특징

| 특징 | 내용 |
| --- | --- |
| 컴퓨터 접근 | 연결된 앱이 있으면 그것을 쓰고, 없으면 컴퓨터 사용(computer use)으로 처리한다. 노트북을 닫아도 작업이 계속된다. |
| 메시지로 설정 | 일을 설명하고 요청에 따라 접근 권한을 준다. 워크플로 빌더는 없다. 데스크톱과 iPhone·Android 앱에서 같은 Bot을 쓴다. |
| 협업 | Bot끼리 병렬로 돌고, 서로 메시지를 보내고, 그룹 채팅에서 컨텍스트를 공유하며, 작업 소유권을 넘긴다. |
| 시연 학습 | 여러 단계 경로를 한 번 보여 주면 Bot이 **스킬**로 저장하고 일정에 맞춰 다시 실행할 수 있다. |
| 누적 컨텍스트 | 이름 붙은 Bot은 세션을 넘어 메모리, 파일, 브라우저 세션, 선호를 유지한다. |

## 3. 공유 컴퓨터

- 한 계정의 모든 Bot은 **클라우드 컴퓨터 하나를 공유**한다(파일, 브라우저 세션, 앱 로그인 포함). 그래서 매번 설정하지 않고도 인수인계가 된다.
- 컴퓨터는 Bot이 아니라 계정에 속한다. 올려 둔 것은 모든 Bot이 쓸 수 있다.
- 사용자 간 격리는 엄격하다.
- 팀원의 공유 Bot과 대화하면 보통 내 컴퓨터에서 실행된다.
- 상세: /grok-bot/computer-and-apps

> 기존 조사 메모의 "봇마다 컴퓨터 하나"와 다르다. 공식 문서 기준으로는 계정당 하나다.

## 4. 첫 위임 예시

여러 도구를 거치고 끝이 분명한 작업이 좋다. 문서의 예:

1. CRM에서 주간 파이프라인 리뷰 목록을 가져온다.
2. 이미 진행 중인 시퀀스에 있는 연락처는 건너뛴다.
3. 상위 5개 계정을 웹과 Slack에서 조사한다.
4. 관련 연락처를 가져온다.
5. 사용자 말투로 아웃리치 초안을 쓰고, 다음 날 아침까지 승인용 초안으로 남긴다.

결과를 검토·교정한 뒤 안정된 절차는 스킬이나 루틴으로 만든다.

## 5. X에서 @bot 태그

- 게시물이나 답글에 **@bot**을 태그하면 메인 Bot이 그 게시물을 작업으로 받고, @bot이 짧은 공개 확인 글을 올린다.
- Grok 계정에 X 계정이 연결돼 있어야 한다.
- 아직 모든 지역에서 쓸 수 있지는 않다.
- 상세: /grok-bot/tag-on-x

## 6. 플랫폼

- 데스크톱: macOS(Apple silicon, Intel), Windows(x64, Arm64), Linux(x64, Arm64)
- 모바일: iPhone, Android
- Bot 컴퓨터는 Cursor의 클라우드에서 돈다.

## 7. 접근 권한과 가격

- **The X Subscription**: Premium, Super, Ultra에 포함(개인·팀 좌석). 사용량은 Cursor, Grok 앱과 공유하는 주간 풀에서 차감된다.
- **기존 Cursor 플랜**: 유료 개인 플랜 전부와 Cursor Teams에 포함.
- **연결 구독**: 개인 SuperGrok, SuperGrok Plus, SuperGrok Heavy, X Premium+ 구독을 연결할 수 있다.
- **Grok Business**: 셀프서브 Grok Business 플랜의 좌석.
- 사용량은 매주 초기화된다.
- 전체 표: /x-subscription/grok-bot, https://cursor.com/help/grok-bot/plans

## 8. 메모리와 컨텍스트

- **Bot별 유지**: 안정적인 선호, 역할 컨텍스트, 이전 작업 요약. 대화와 학습 컨텍스트는 Bot마다 분리된다.
- **Bot 간 공유**: 이름, 시간대처럼 사용자에 관한 소수의 사실.
- **공유로 이동**: 공유 파일, 브라우저 세션, 직접 인수인계.
- 중요한 결정은 메모리에 의존하지 말고 Bot에게 현재 출처를 확인하게 한다.
- 상세: /grok-bot/bots#what-a-bot-remembers

## 9. FAQ 요점

- **노트북을 닫으면**: 작업은 클라우드에서 돈다. 앱, 노트북, 폰을 닫아도 백그라운드 턴이나 루틴은 멈추지 않는다.
- **동시성**: 여러 Bot이 동시에 일한다. 각자 공유 컴퓨터에서 자기 화면을 갖고, Bot마다 computer-use 작업은 한 번에 하나만 돌린다.
- **웹사이트**: 연결된 앱이 없는 서비스를 포함해 많은 브라우저 기반 도구를 쓸 수 있다. 사이트가 자동화를 막거나, 세션이 만료되거나, 사람이 해야 하는 단계가 있을 수 있다. 그럴 때 Bot은 그 단계를 사용자에게 넘긴다.

## 11. 이 프로젝트와의 관련

- **루틴 실행**: "앱을 닫아도 루틴이 돈다"는 점은 장바구니 만료와 도착 약속 시각 브리핑을 Bot 루틴으로 구현할 가능성을 뒷받침한다. 루틴 정의 형식은 `skills-routines-and-automations`에서 확인해야 한다.
- **승인 요청**: "필요하면 승인을 요청한다"는 것은 예외 알림 기능과 대응한다. 외부로 알릴 수 있는지는 `security`(승인과 Auto Review)에서 확인해야 한다.
- **작업 전달 경로 후보 추가**: 메시지 입력과 X의 @bot 태그가 공식 경로다. 다만 이 페이지에는 API·webhook이 없다. 완료 신호 경로 검증(CLAUDE.md의 최우선 리스크)은 `get-started`, `bots`, `skills-routines-and-automations`, `tag-on-x`를 읽어야 결론이 난다.
- **Bot 병렬 실행**: Bot마다 computer-use 작업이 한 번에 하나라서, 묶음 전체를 한 Bot에 넘길지 Bot을 나눌지 설계에 영향이 있다.
