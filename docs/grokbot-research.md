# 그록봇(Grok Bot) 조사 메모

조사일: 2026-11-01. 1~6절은 대부분 2차 자료(블로그, GitHub 저장소)이고 xAI 공식 문서는 확인하지 못했다. 출처끼리 날짜와 세부 내용이 어긋나는 곳이 있어 1~6절은 "미확정"으로 취급한다. **7절은 그록봇에게 직접 질문하고 실제로 실행하게 해서 얻은 결과**이며, 1~6절과 겹치면 7절을 우선한다.

## 1. 그록봇이 무엇인가

- xAI의 상시 가동 컴퓨터 사용(computer-use) 에이전트. Grok 챗봇과는 별도 앱이다.
- 2026-08-11 베타 출시. 출시 문구: "작업을 주고, 컴퓨터를 끄고, 어디서든 연락하라."
- 봇마다 영구 클라우드 가상 컴퓨터(브라우저, 파일 접근, 자체 로그인)를 하나씩 가진다. 사용자 기기가 꺼져도 작업이 계속된다.
- 커넥터나 API 없이 사이트·앱의 화면을 직접 클릭하고 입력해서 일한다. 사용자가 자기 도구에 로그인해 준다.
- 세션 간 기억을 유지하고 사용자 교정을 반영한다.
- 봇끼리 조율하고 컨텍스트를 주고받을 수 있다(한 에이전트가 다른 에이전트를 지휘).
- **teach-a-task**: 한 번 시연하거나 화면을 녹화하면 반복 가능한 루틴/스킬로 만든다.
- **루틴**: 고정 시각에 시작하도록 예약할 수 있다.
- **승인**: 매 단계가 아니라 민감한 행동 전에 멈추고 사람의 승인을 요청한다. 알려진 유일한 안전장치다.
- 고유 이메일 주소가 있다(mail.grokbot.com, 봇에게 직접 요청해서 받는다).
- 자격 증명 저장·보호 방식은 공개 자료에 없다.

| Cursor Teams Premium | 좌석당 월 $120. 중앙 결제, 팀 봇 마켓플레이스, 분석, SSO |

- 플랫폼: macOS, Windows, Linux 데스크톱, iOS. Android는 예정.
- 배경: 2026-06 SpaceX가 Cursor 인수에 합의했고, 다운로드와 온보딩은 Cursor 인프라를 통한다. xAI는 스스로를 SpaceXAI로 소개한다.

## 3. 해커톤에서 관찰된 정의·운용 방식

참고한 저장소 두 곳(2026 가을 SpaceXAI 해커톤 관련):

**BR1K0/grokbot-project** (Track 4: "Grokbot definition (instructions, skills, routines, tests)")
- 봇 정의는 파일 묶음이다: `bot/instructions.md`(지침), `bot/TEAM.md`(팀 조율), `bot/skills/*.md`(재사용 절차), `bot/routines/`(Slack 트리거와 스케줄, 예: 22:00 야간 토너먼트), `bot/team/`, `bot/connections.md`, `tests/prompts.md`(봇 테스트 프롬프트).
- skill·routine 파일의 내부 형식은 해당 페이지에 문서화되어 있지 않다.
- **작업 전달**: Slack 채널에 평문으로 요청하거나 봇을 멘션한다("@simon run tournament", PR 리뷰 코멘트 수정 요청 등).
- **완료 신호**: 봇이 같은 스레드에 태그 붙은 메시지를 올린다(`[RUN DONE]`, `[LEVEL READY]`, `[PATCH READY]`, `[ROUND OVER]` 등). 봇은 자기 머신, 브랜치, PR에서 작업한다.

**Dv04/Team-Masala-Grok-Hackathon PR #1** (3시간·4인 해커톤 스타터)
- 트랙은 대회 시작 시점에 공개된다. 실제 xAI 연동은 "어댑터 계약"으로 비워 둔 상태이며, 공식 그록봇 API·SDK·엔드포인트·인증 방식은 어디에도 명시되지 않았다.

## 4. 이 프로젝트에 미치는 시사점

- **완료 신호 경로(CLAUDE.md의 최우선 리스크)**: 확인된 공개 경로는 Slack 같은 메신저의 멘션과 스레드 메시지뿐이다. 공식 API나 webhook은 확인되지 않았다. 따라서 본 버전의 "텔레그램 → 에이전트 → hook 감지" 구조는 가정이다. 다음 중 하나로 우회할 수 있다.
  1. 메시지 채널(Slack 등)로 전달하고, 봇의 완료 메시지를 태그로 감지한다.
  2. 그록봇의 고유 이메일로 전달하고 회신 메일로 감지한다.
  3. 해커톤 현장에서 주최 측이 제공하는 연동 수단을 확인한다.
- **루틴과 스케줄**: "도착 약속 시각에 브리핑 전송"과 "장바구니 만료"는 그록봇 자체 루틴 기능으로 구현할 수 있을 가능성이 있다. 다만 루틴 정의 형식은 미확인이다.
- **승인 요청**: 그록봇이 민감한 행동 전에 멈추는 동작이 "예외 알림(권한 승인)" 기능과 직접 대응한다. 이 승인 요청을 외부에서 가로채 BLE 버튼·현황판으로 전달할 수 있는지는 미확인이다.
- **상시 가동 + 기기 꺼짐 허용**: "맡기고 떠난다"는 포지션과 일치한다. 데모에서 노트북을 닫고 현황판만 켜 두는 시나리오가 가능하다.
- **봇 정의가 파일(md)로 관리됨**: MVP인 "스킬 지침" 방식(시간 추정 → 기준 미달 시 묶을 작업 요청)을 `instructions.md`/`skills/*.md`로 옮겨 쓸 수 있을 가능성이 있다.

## 5. 하드웨어 보드 메모 (참고)

- NU-40 DK: nRF52840 기반, BLE 5.4, 아두이노 IDE 호환. 공개 예제가 많다(OLED 버스 알림판, 주식 티커 등).
- NU-87 TinyDK: Realtek RTL8720DF(RTL872xD, AmebaD) 기반, BLE 5.0, 아두이노 IDE 호환. Zephyr에 보드 지원이 올라와 있다.
- hyeonmaek/firmware 저장소가 NU-40 단말과 NU-87 기지국(게이트웨이)을 함께 쓰는 사례다. 해커톤과의 관련성은 미확인.
- NU-87이 Wi-Fi를 지원하는지, 현황판을 NU-87 단독으로 갱신할 수 있는지는 이번 조사에서 확인하지 못했다.

## 6. 아직 모르는 것 (해커톤 현장에서 확인할 목록)

1. 공식 그록봇 API, webhook, SDK 존재 여부와 인증 방식.
2. 외부에서 작업을 주입하는 공식 경로(메신저, 이메일, 기타)와 완료 이벤트를 받는 방법.
3. 루틴·스킬 파일의 정확한 형식.
4. 승인 요청을 외부로 알릴 수 있는지.
5. 해커톤 참가자에게 그록봇 계정(구독)이 제공되는지, 요청량 제한이 있는지.
6. 이번 해커톤의 공식 트랙과 평가 기준.

## 7. 그록봇 직접 확인 결과 (2026-11-01)

그록봇에게 질문 31개([grokbot-questions.md](grokbot-questions.md))를 주고, 할 수 있는 건 직접 실행하게 했다. 표시는 그록봇이 붙인 것이다. [확인함]은 실제로 실행해 봤다는 뜻이고, [추정]은 그록봇의 자기 설명이다.

### VM 환경
- [확인함] Debian 13(trixie), 8코어, 메모리 15GB, 디스크 128GB.
- [확인함] 터미널 명령 실행 가능. Python 3.13.5, Node v24.22.1, npm 11.21.1.
- [확인함] venv 안에서 `pip install`, `npm install`, GitHub `git clone` 모두 성공. 시스템 파이썬보다 venv 권장.
- [추정] 외부 인터넷 접속 가능(example.com, pypi.org, api.github.com 확인). 막힌 도메인 목록은 모른다.
- [확인함] 파일은 계속 남는다. 작업 파일은 주로 `/workspace`에 둔다. **단, 컴퓨터를 리셋하면 마지막 스냅샷으로 돌아가 최근 파일이 사라질 수 있다.**

### 브라우저와 HTTP
- [확인함] 브라우저로 접속, 입력, 클릭, 결과 읽기 가능. **셸보다 느리고 봇당 브라우저 작업은 한 번에 하나뿐**이다.
- [확인함] `curl`로 아무 URL에나 HTTP POST를 보내고 JSON 응답을 파싱할 수 있다.

### 스킬, 지침, 루틴
- [확인함] 사용자 스킬 경로는 `/home/box/agent-data/workflows/<slug>/SKILL.md`. YAML 프런트매터에 `name`, `description`(언제 쓰는지)이 필수이고 본문은 자유 형식이다. 저장하면 모든 봇이 같이 쓰고, `description`에 맞는 상황에서 불러온다.
- [추정] "매 작업 전에 X" 같은 규칙은 봇 프로필 description이나 장기 기억에 넣는다. 잘 지키지만 100% 보장은 없다. 그록봇 스스로 "도구 쪽에 강제 장치(예: 시작 기록이 없으면 종료 기록 거부)를 두라"고 권했다.
- [확인함] 루틴 = 저장된 프롬프트 + 트리거. 시각 트리거는 사용자 시간대 기준 5필드 cron(최소 간격 5분). 이벤트 트리거는 Slack 멘션·키워드, GitHub, 이메일 수신, **외부 POST로 실행되는 webhook**.
- [모름] teach-a-task의 녹화 시작 위치. 결과물은 루틴이 아니라 스킬이다.

### 시간 기록
- [확인함] 메시지마다 KST 타임스탬프가 붙고 `date`로 현재 시각을 알 수 있다.
- [모름] 작업별 시작·종료 기록이나 소요 시간 이력은 없다. 대화 기록의 메시지 시각으로 대략 역산할 수만 있다.
- [추정] 사전 추정은 단계 수, 브라우저 필요 여부, 로그인·승인 개입, 비슷한 경험을 근거로 대략 할 수 있지만 정확도는 낮다.
- [추정] 대기 시간은 자동 구분되지 않는다. 승인 대기는 승인 카드 전후 시각으로 구분할 수 있다.

### 알림과 외부 연동
- [확인함] 기본 완료 알림은 앱 채팅 메시지. 연결된 Gmail로 메일 발송 가능(타인에게 가는 메일은 초안 확인을 거친다).
- [확인함] 작업 종료 시 지정 URL로 POST(webhook 발신) 가능. 루틴 프롬프트에 넣어도 된다.
- [추정] 승인 카드는 앱 안에서만 뜬다. 그록봇이 승인 요청 직전에 직접 webhook이나 메일을 보내는 식으로 외부에 알릴 수 있다.
- [확인함] 전용 이메일 주소가 있지만 현재 꺼져 있다. 켜면 메일 수신 트리거 루틴을 만들 수 있다.
- [확인함] **외부에서 작업을 넘기는 공식 방법은 webhook 트리거 루틴**이다. 루틴 패널에서 URL과 발신 키를 복사해 POST하면 그록봇이 깨어나 작업한다. 공개 SDK는 모른다.
- [모름] 외부에서 상태를 조회하는 API는 없다. 상태가 바뀔 때 그록봇이 우리 서버로 POST하는 push 방식이 현실적이다.
- [확인함] 다른 봇과 직접 메시지, 단체 채팅방, 같은 컴퓨터의 파일로 정보를 주고받을 수 있다.

### 제한
- [추정] 백그라운드 작업은 동시에 2~4개 정도가 적당하다. 브라우저 작업은 봇당 하나.
- [확인함] 셸 명령 하나는 최대 13분 기다린다. 더 긴 건 백그라운드로 돌린다. 작업 전체 상한은 모른다.
- [모름] 플랜별 사용량 한도의 정확한 숫자. X 읽기는 분당 30회, 하루 1000회 [확인함].
- [확인함] 타인에게 가는 메시지, 결제, 삭제 같은 되돌릴 수 없는 작업은 먼저 묻는다. 위험해 보이는 명령은 자동 검토에 막힐 수 있다. 루틴 실행 중에는 저장된 로그인이나 카드를 혼자 채울 수 없다.

### 6절 미확인 목록의 상태
1. 공식 API·webhook: **webhook 트리거 루틴(수신)과 curl POST(발신)는 확인**했다. SDK와 상태 조회 API는 없거나 모른다.
2. 작업 주입·완료 이벤트 경로: 주입은 webhook 루틴, Slack 멘션, 이메일. 완료는 그록봇이 우리 URL로 POST하는 방식.
3. 스킬 파일 형식: 확인함(위 참고). 루틴은 대화로 만들며 파일 형식은 따로 확인하지 않았다.
4. 승인 요청 외부 알림: 자동 전달은 안 된다. 그록봇이 직접 알리는 방식으로 우회할 수 있다.
5. 계정·요청량 제한: 일부만 확인함(위 참고).
6. 해커톤 공식 트랙과 평가 기준: 아직 모른다.

### 그록봇의 추천
VM에 설치하는 CLI로 기록하고(`/workspace`에 JSONL이나 SQLite), 사람이 보는 통계·대시보드만 웹으로 덧붙이라고 권했다. 이유는 셸이 가장 빠르고 확실하며, 명령 한 줄이라 빠뜨릴 일이 적고, 브라우저 방식은 느린 데다 봇당 하나뿐인 브라우저를 실제 작업과 다투기 때문이다. "작업 전에 시작 기록" 규칙을 스킬로 저장하면 다른 봇도 같이 쓸 수 있다고 했다.
